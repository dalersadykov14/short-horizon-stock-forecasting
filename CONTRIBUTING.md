# Contributing to short-horizon-stock-forecasting

Thank you for your interest in contributing to this project! We welcome contributions from the community to help improve and expand this stock forecasting evaluation framework.

## How to Contribute

### Reporting Issues
- Use the GitHub issue tracker to report bugs or suggest enhancements
- Before creating a new issue, please search existing issues to avoid duplicates
- Provide clear descriptions, including steps to reproduce bugs and expected behavior

### Submitting Changes
1. **Fork the repository** and create a new branch for your feature or bugfix
2. **Make your changes** following the project's coding style and conventions
3. **Test your changes** thoroughly to ensure they don't break existing functionality
4. **Document your changes** by updating relevant documentation and comments
5. **Submit a pull request** with a clear description of your changes and their purpose

### Pull Request Guidelines
- Keep changes focused and atomic - one feature or fix per PR
- Write clear, descriptive commit messages
- Include tests for new functionality when applicable
- Ensure all existing tests pass before submitting
- Update documentation to reflect your changes

### Code Style
- Follow PEP 8 style guidelines for Python code
- Use meaningful variable and function names
- Add docstrings to functions and classes
- Keep functions focused and modular

### Adding New Models
If you're contributing a new forecasting model:
- Implement the model following the existing model interface
- Include comprehensive documentation of the model's methodology
- Add appropriate tests to validate the model's functionality
- Update the README.md to include the new model in the Models section

### Improving Documentation
Documentation improvements are always welcome:
- Fix typos or clarify unclear sections
- Add examples or usage scenarios
- Expand methodology explanations
- Improve reproducibility instructions

## Development Setup

1. Clone your fork of the repository
2. Create a virtual environment: `python -m venv .venv`
3. Activate the virtual environment:
   - Linux/Mac: `source .venv/bin/activate`
   - Windows: `.venv\Scripts\activate`
4. Install development dependencies (when available)
5. Make your changes and test thoroughly

## Testing

Please ensure your changes don't break existing tests. Run the test suite before submitting a pull request. If you add new functionality, include appropriate tests.

## Questions?

If you have questions about contributing, feel free to open an issue for discussion or reach out to the maintainers.

## Code of Conduct

Please be respectful and constructive in all interactions with the community. We aim to foster a welcoming and inclusive environment for all contributors.
